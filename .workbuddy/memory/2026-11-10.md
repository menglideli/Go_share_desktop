# 2026-11-10 · P1-6 复测 + P0-2 真 60fps（发现 DXGI 重建掉速 bug）

接手状态见 `2026-11-09.md` 第八节。今天解锁后按清单依次做完。

## 一、P1-6 延迟收益（A/B 实测）

同一脚本、同一区域（副屏 1920×1080）、1 观众，只改 `emit` 里预览与发送的先后：

| 顺序 | 观众端「延迟」 | 分享端「预览」 |
|---|---|---|
| 旧：预览在发送前 | **5 ms** | 1.8~2.0 ms |
| 新：预览在唤醒后 | **1~2 ms** | 1.6~3.0 ms |

差值 ≈ 预览耗时，判据（3~6ms）取到下限。区域 1280×720 时新顺序 0~1ms。
预览在 2K 全屏下会到 6~9ms（A/B 时实测），所以这一项对"整屏分享"收益最大。

## 二、P0-2：让「流畅60」真的按 60fps 采集

做法：
- `pipeline.captureFPSFor(preset, region, display)`：`MaxFPS` 驱动采集帧率，
  但**超过 2.5M 像素自动回落 30**（2K 编码 10~15ms，60fps 预算 16.7ms 不成立）；
  "最大/急速"保持 30（60fps 会让带宽翻倍，这两个档的承诺不是高帧率）。
- `-fps` 可覆盖；`-region` 让"一开始就分享小区域"可测。
- 面积变化（换区域/换屏）时重算帧率并重建采集源；日志每 3 秒给
  `X fps（采集 Y · 目标 Z）`，启动时说明是否回落。

实测（60Hz 动画窗口 + 1 观众）：
- 1280×720 + 流畅60：分享 **54~60 fps**、观众 **52~53 fps**、延迟 2~3ms、队列丢弃 0；
- 2K 全屏 + 流畅60：稳定 **30 fps**、编码 10.1ms、日志写明回落原因。

## 三、最重要的发现：重建采集源不能"先建后换"

第一版按 `captureFPSFor` 在换区域时重建采集源（照搬 `SetDisplay` 的"先建新源、
再关旧源"）。结果切换后新源只有 **~19fps**，而且不会自愈：

- 同样内容、同样 `FPS:60`，**独立进程**里 `NewSource` 能跑到 55fps；
- 目标帧率日志显示 60、编码只要 2.6ms、`播放队列丢弃 0` —— 只有采集侧慢；
- 换区域但**不重建**（`-fps 30` 固定）时 30fps 完全正常。

结论：同一显示器上短暂两路 DXGI duplication 并存，会让新流被限速。改成
**先关旧源再建新源**（Run/Stats 加空源保护；新建失败按旧参数恢复）后，
切换后稳定 54~60fps。

**教训**：任何"重建采集源"的路径都要先关后建；"先建后换"在 UI 上是无感的，
但在 DXGI 侧是有代价的，而且只体现在 fps 上 —— 不看 `采集 fps` 根本发现不了。

## 四、环境：60fps 长跑会把机器烤热

60fps 编码跑几分钟后，`codeccheck 2K 全量` 从 **16.9ms 涨到 21~23ms**
（阈值 33.3ms 合计，反复假红）；静置 60 秒回到 16.9ms / 15 项全绿。
**验证顺序：性能类自检放在 60fps 长跑之前。**

## 七、P0-3 光标独立图层（同日晚）

**做法**：`CtlHello` 能力协商 → 全员声明才停止"画进帧"；形状 `CtlCursorShape`
（内容哈希 id + BGRA，2 秒补发）、位置 `CtlCursorPos`（60Hz、25 字节，
绝对坐标 + 区域原点）；观看端按 `now + 偏移 - D` 取采样，contain/1:1 两套映射。

**实测（副屏 1080p 静止 + 鼠标画圈 14 秒）**

| 观众 | 分享端出网 | 帧率 | 观看端 |
|---|---|---|---|
| 新版 | **0.00 Mbps** | 0 fps | 光标流 采样16 形状#a9157ebb |
| `-no-cursor-cap`（模拟旧版） | 1.76~8.72 Mbps | 30 fps | 光标流 未收到（帧内光标） |

离屏断言：1.0x 落点偏差 (0,-1)、1.75x (1,1)，尺寸随画面缩放；`uicheck` 15/15。

**关键取舍/坑**

- 不能"先建后换"的教训同样适用于能力切换：`SetDrawCursor` 用原子量，
  采集线程每帧读；重建采集源后要重新落一次（`applyCursorMode`）。
- 分发形状要"变化时立即 + 每 2 秒补发"：中途接入的观众不需要额外请求消息。
- id 必须用**内容哈希**，不能拿 HCURSOR 句柄 —— 句柄会被系统复用成别的形状。
- 分享端本地回显不含光标（主窗最小化时无所谓）；混合新旧观众时退回帧内光标。

**坐标链路真机验证**：鼠标移到副屏 (3200,500)（副屏原点 2880），观看端日志
`光标流 ... 图像坐标(320,500)` —— RX/RY 与热点的换算准确。合成落点由两条离屏
用例覆盖（1.0x 偏差 (0,-1)、1.75x (1,1)）。

**注意**：`-display 1` 时如果鼠标在**主屏**上，图像坐标会是负数（在采集区域外），
UI 会按窗口裁剪不画 —— 这是正确行为，不是 bug。
