## 本次踩到的坑（都已写进 PLAN 风险登记 R18~R23）
1. **外部 SetWindowPos 移动 Gio 窗口 → 不再产生帧事件**（停在第 10 帧；不移动可跑 889 帧）。改用「采集副屏、观看窗留主屏」。
2. **RGB↔YUV 范围不匹配**：编码用 limited-range 而解码按 full-range → PSNR 23dB 且"提质量无改善"。统一 BT.601 full-range 后 34.8dB。
3. **解码画布并发访问**：解码器持久画布直接交给 Gio 渲染 → 撕裂/崩溃（退出码 0xCFFFFFFF）。改用画布池 + 渲染完归还。
4. **限帧判定卡边界**：严格 `< interval` 让 30fps 档只发 19.7fps。加 3ms 容差后 28.9fps。
5. **重组槽按数量清理误删活跃帧**：不可靠无序通道下分片乱序，活跃帧数超预期。只能按超时清理。
6. **别用随机噪声模拟桌面变化**：JPEG 对噪声 PSNR 崩到 20dB 以下，看着像编码坏了。
7. **采集耗时度量口径**：`WaitFrame` 含阻塞等待（DXGI 变化驱动），不能当 CPU 开销。拆分后：2K 等待 45.2ms / **处理仅 1.20ms**。
8. Gio 关窗后进程不退出 → 兜底 os.Exit(0)。

# 追加：修复"观看窗全黑"（用户报障）

**用户报障**：`sharedemo.exe` 里面全黑，看不见东西。

## 根因（R24）
`internal/ui/viewer.go` 的 `layoutStatusBar2` 里 `paint.PaintOp{}` **漏了 clip**。
Gio 的 `PaintOp` 填充的是"当前裁剪区域"，`layout.Rigid` 不会替调用方设裁剪 →
状态栏的面板色铺满**整个窗口**，把先画好的视频画面整块盖掉。
文字是后画的所以幸存 → 症状是"全黑，只剩状态栏文字"。

阶段 1 的 `preview.go` 本来有 `clip.Rect`，阶段 2 重写观看端时漏掉了；
而且 `clip.Rect{Max: gtx.Constraints.Max}` 在 Rigid 里也是错的（Max = 整窗尺寸）。
两处统一改成 **"op.Record 先量内容高度 → 按该高度 clip 画背景 → 播放内容"**。

## 排查路径（值得复用）
1. 日志显示渲染 889 帧 + `画面 true` → 帧存在，黑在链路后段
2. `cmd/pixprobe` 分三个观测点统计：采集源 98.2%/212 → 编码 17 条带 → 解码 98.1%/212.4，**全正常**
3. `cmd/shot` 截屏 → **图像区域纯黑但状态栏文字清晰** = 渲染管线是活的，是"画了被盖住"
4. `cmd/gioimgtest`（已删）最小复现：640×360 直连 layout 正常 → 排除 Gio 本身
5. `cmd/viewertest` 隔离实验：同一 `RunViewer` + 自造亮图 → 也黑 → 锁定 viewer 内部
6. 最终对照 `preview.go` 的老写法发现缺 clip

## 验证
- 修复版：画面正常，28.7fps / 7Mbps（`out/shot-final.png`）
- **反向变异**：去掉那行 clip → 立刻复现全黑（`out/shot-mutate2.png`）→ 因果闭合

## 教训（R26，最重要）
阶段 1/2 对"画面能显示"的验证只用了 `IsWindowVisible` + 渲染帧计数 ——
**画面被完全盖住时这两项依然全部通过**。这个 bug 穿过了整个阶段 2 的验证。
→ **凡涉及画面输出的改动，必须用像素证据收口，不要只信日志。**
