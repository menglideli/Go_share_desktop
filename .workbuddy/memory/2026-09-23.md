## 追加：跨设备分辨率适配（用户提出 2K 共享给 1K 屏看不清）

已实测并写入 PLAN.md 3.4，复现代码 `spike/scalebench`（`go run .`）。

**实测硬结论（i7-13700H 20 线程，CGO_ENABLED=0，源 2880×1800）**
- BGRA→I420：单线程 **26.14 ms**（超 30fps 预算）→ 并行 20 workers **4.29 ms**（6× 加速）
- RGBA 域缩放（x/image/draw）**完全不可用**：NearestNeighbor 63ms / ApproxBiLinear 110ms / BiLinear 174ms / CatmullRom 259ms
- I420 域缩放：box 2:1 单线程 4.88ms → 并行 **1.10ms**；bilinear 9.94ms → 并行 **2.05ms**
- 完整流水线并行：[A] 原生直发 2K **4.21ms** / [B] I420→box2:1 5.16ms / [C] BGRA box2:1→I420 **3.26ms** / [D] I420→bilinear 5.65ms

**架构决策**
- 必须并行化；**缩放只能在 I420 域做**（比 RGBA 域快 20~60×）
- 转换+缩放仅 4~6ms，编码才是大头 → **默认有能力直发原生分辨率**
- 降采样不可逆，优先"发原生 + 观看端缩放"，而非发送端预降
- 宽高比必须 contain（16:10→16:9 拉伸会变形），留黑边
- 四个子问题：宽高比、降采样糊文字、DPI 物理/逻辑像素混淆、降采样不可逆
- 观看端必备：1:1 原始尺寸 + 平移（看代码刚需）、区域放大 200%/400%
- 分辨率变更需重建编码器+发 IDR → 迟滞：变化 >20% 且持续 3s
- 多观看者不同需求 → 档位归并 ≤2 档，避免 N 个编码器

**新增阶段 0 spike**：S0-6 go264 编码 2K 耗时（<20ms/帧）、S0-7 观看端解码+GPU 缩放渲染清晰度
